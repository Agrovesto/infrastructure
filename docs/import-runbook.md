# Import runbook: adopting the existing AWS resources

Order: **bootstrap → prod → monitoring → dev**. Region is `eu-west-1`.
Prod and monitoring share one state key and are separated by **workspace**: prod uses `default`, monitoring uses `monitoring`.

| File | Purpose |
|---|---|
| `<stack>/imports.tf` | One-shot `import` blocks. Delete the file once the stack plans with "No changes". |
| `prod/legacy.tf`, `monitoring/legacy.tf` | Existing resources imported as they are (config generated by Terraform, then cleaned). Excluded from checkov, trivy and coverage. |
| `prod/legacy_lambda_placeholder.zip` | Placeholder `filename` for the 3 legacy Lambdas. `ignore_changes` keeps their real code. |
| `bootstrap/{dev,prod}.tfvars` | Per-account bootstrap values. Bootstrap uses local state. |
| `scripts/fix_generated.py` | Cleans `terraform plan -generate-config-out` output. Needed only for dev. |

**Rule for every apply: the plan must show 0 to destroy and nothing "must be replaced".**

## 1. Bootstrap (per account, local state)

```bash
cd bootstrap && terraform init
AWS_PROFILE=agrovesto-prod terraform plan -state=prod.tfstate -var-file=prod.tfvars -out=prod.tfplan
AWS_PROFILE=agrovesto-prod terraform apply -state=prod.tfstate prod.tfplan

AWS_PROFILE=agrovesto-dev terraform plan -state=dev.tfstate -var-file=dev.tfvars -out=dev.tfplan
AWS_PROFILE=agrovesto-dev terraform apply -state=dev.tfstate dev.tfplan
```

Before the dev plan:
- Run `aws iam list-attached-role-policies --role-name nomaos-dev-github-terraform`.
- Set `deploy_admin_access` and `import_deploy_policy` in `dev.tfvars` to match what is attached.

The dev trust policy is rewritten to exactly the `github_sub_patterns` in `dev.tfvars`.

## 2. Prod

```bash
cd prod && terraform init && terraform workspace select default
AWS_PROFILE=agrovesto-prod terraform plan -out=tfplan
```

Last reviewed plan (2026-09-24): **112 import, 109 add, 110 change, 0 destroy, 0 replace.**

Changes to real resources are limited to the following. Everything else is tags or Terraform-only settings.
- **RDS `migration-prod`** (applied at the next maintenance window):
  - backup retention 2 → 30 days
  - deletion protection on
  - final snapshot on delete
  - the new RDS SG added next to the 2 existing SGs
- **Route tables:** `public[1]` moves to the shared public route table.

The ECS tasks read the DB master login from the existing `nomaosDBcredentials` secret. Before you apply, check that it has `username` and `password` keys:

```bash
aws secretsmanager get-secret-value --secret-id nomaosDBcredentials \
  --query SecretString --output text --profile agrovesto-prod | jq 'keys'
```

`manage_master_user_password` stays off. Turning it on would rotate the live password.

Then:
1. `terraform apply tfplan`
2. `terraform plan` → it must show "No changes".
3. Delete `prod/imports.tf`.

## 3. Monitoring (after prod is applied)

```bash
cd monitoring && terraform init && terraform workspace select -or-create monitoring
AWS_PROFILE=agrovesto-prod terraform plan -out=tfplan
```

The data-source errors for the prod VPC, ALB and ALB security group go away once prod is applied: those lookups need tags and resources that the prod apply creates.

If the plan offers to **destroy Route 53 zones**, you are in the wrong workspace. Stop.

Apply, re-plan until "No changes", then delete `monitoring/imports.tf`.

## 4. Dev

The legacy dev resources have no config yet. The first plan generates it:

```bash
cd dev && terraform init
export TF_VAR_mssql_sa_password='<SA password the dev host uses today>'
AWS_PROFILE=agrovesto-dev terraform plan -generate-config-out=generated_legacy.tf
python3 ../scripts/fix_generated.py generated_legacy.tf --profile agrovesto-dev
mv generated_legacy.tf legacy.tf
AWS_PROFILE=agrovesto-dev terraform plan -out=tfplan
```

Until `dev/legacy.tf` is committed, dev CI fails, because the import blocks point to resources with no config.

Apply, re-plan until "No changes", then delete `dev/imports.tf`.

## 5. Follow-ups (after the import)

| Item | Action |
|---|---|
| `migration-prod` is unencrypted | Planned window: snapshot → encrypted copy → restore → swap. Then set `mssql_storage_encrypted = true`. |
| Prod default SG `sg-05a2722a…` has live rules (RDS and `noma-agx`) | Move the rules to named SGs, then set `manage_default_security_group = true`. |
| Dev host `new-noma-api` (legacy) | Migrate data to the new host, then move EIP `eipalloc-0b7f04c0906f47a4e`. |
| Old ACM `*.nomaos.com` cert, DMS endpoint `agxdb2instance` (its secret is deleted), role `nomaos-bootstrap-dev-deploy` | Unused. Delete them. |
| Dev and prod VPCs are both `172.96.0.0/16` | Re-IP one of them before any peering. |
