# Agrovesto infrastructure (prod)

Terraform for the **prod** AWS account — a containerised production stack:

```
Internet → Route53 (zone owned by THIS account — also holds dev's dev.* records)
        → ALB (public subnets, HTTPS via ACM wildcard cert, host-header routing)
        → ECS Fargate services (PRIVATE subnets, one service per API)
        → RDS SQL Server (Multi-AZ, database subnets, one database per service)
```

```
prod/
├── versions.tf              # terraform block, S3 backend, provider
├── variables.tf             # every input for the stack
├── locals.tf                # naming, NAT/AZ logic, DNS maps, db-init SQL
├── data.tf                  # AZs, account/region, ELB service account, IAM docs
├── vpc.tf                   # VPC, IGW, public/private/db subnets, NAT, route tables
├── security_groups.tf       # ALB (80/443 world) → ECS (service ports) → RDS (1433)
├── ecr.tf                   # one ECR repo per service, scan-on-push, lifecycle rules
├── iam.tf                   # ECS task execution/task roles, RDS monitoring role
├── ecs.tf                   # cluster, task definitions, Fargate services (private subnets)
├── alb.tf                   # internet-facing ALB, access logs, target groups, listeners
├── acm.tf                   # wildcard cert (*.<domain> + apex), DNS-validated
├── rds.tf                   # SQL Server instance, generated master password, db-init task
├── route53.tf               # hosted zone + alias A records per service
├── outputs.tf
├── terraform.auto.tfvars    # committed, secret-free values (auto-loaded)
├── checkov.yml  trivy.yml  trust-policy.json
└── README.md
```

## What gets created

| Piece | Details |
| --- | --- |
| VPC | `10.30.0.0/16`: 2 public subnets (ALB), 2 private subnets (ECS tasks), 2 database subnets (RDS), IGW, one NAT gateway per AZ (`single_nat_gateway=true` halves NAT cost) |
| ALB | Internet-facing, drops invalid headers, access logs to S3, HTTP→HTTPS redirect, HTTPS with ACM wildcard cert, host-header rules per service, default 404 |
| ACM | `*.nomaos.com` + apex, DNS-validated through the Route53 zone |
| ECS | Fargate cluster (`agrovesto-prod`) with 5 services in the **private subnets**, no public IPs, deployment circuit breaker with rollback, CloudWatch logs (30d), Container Insights |
| ECR | One repo per service: `agrovesto-prod-wallet`, … Scan-on-push, immutable tags, keep last 10 tagged images |
| RDS | SQL Server (`sqlserver-se` default), Multi-AZ, encrypted gp3 with autoscaling, 30d backups, enhanced monitoring, logs to CloudWatch. Master password is **generated by Terraform** and stored in Secrets Manager (`agrovesto-prod-mssql-master`) |
| Route 53 | **Authoritative for the whole domain**: hosted zone, alias per prod service → ALB, and dev's `*.dev.nomaos.com` records via `extra_a_records` / `extra_cname_records` |

Every task gets `PORT`, `DB_HOST`, `DB_PORT`, `DB_NAME` (service name ==
database name, dev convention) as environment variables and `DB_USER` /
`DB_PASSWORD` injected from Secrets Manager.

## One-time setup (prod account)

1. **Terraform state bucket** — create `nomaos-tfstate-<prod-account-id>-eu-west-1`
   (same convention as dev) and replace `PROD_ACCOUNT_ID` in `versions.tf`.
2. **GitHub OIDC deploy role** — in the prod account create the OIDC provider
   (`token.actions.githubusercontent.com`) and an IAM role whose trust policy
   matches `trust-policy.json` (replace `PROD_ACCOUNT_ID`, adjust the repo
   `sub` pattern if the repo moves). Store the role ARN as the repo secret
   **`AWS_PROD_ROLE_ARN`**.
3. **Install the workflow** — `cp prod.workflow.yml .github/workflows/prod.yml`
   (see the repo-root README).

The prod workflow then plans on PRs to `main` and applies on push to `main`.

## First apply & images

`terraform.auto.tfvars` ships a placeholder image (`ealen/echo-server`) that
serves HTTP on `$PORT`, so the first apply stands the whole stack up healthy.
Then:

```bash
# build, tag, push (once the workflow has created the repos)
aws ecr get-login-password --region eu-west-1 | \
  docker login --username AWS --password-stdin <acct>.dkr.ecr.eu-west-1.amazonaws.com
docker build -t <acct>.dkr.ecr.eu-west-1.amazonaws.com/agrovesto-prod-wallet:v1 .
docker push <acct>.dkr.ecr.eu-west-1.amazonaws.com/agrovesto-prod-wallet:v1
```

and set `services.wallet.image` in `terraform.auto.tfvars` to the pushed tag.
Docker Hub pulls go through the NAT gateway; mirror the placeholder into ECR
if you expect frequent task churn.

## The 5 databases

RDS cannot create databases via Terraform, so there are two ways:

- **Automated (recommended)** — set `run_db_init = true` in
  `terraform.auto.tfvars`: after the instance is created, Terraform starts a
  one-off Fargate task (`mcr.microsoft.com/mssql-tools`, driven from the CI
  runner through the AWS API — no VPC access needed) that runs
  `IF DB_ID(...) IS NULL CREATE DATABASE [...]` for every name in
  `mssql_databases`. Re-runs automatically when the list changes.
- **Manual runbook** — connect to the instance from inside the VPC (e.g. an
  ad-hoc Fargate task in the ECS security group) and run the SQL printed in
  the `mssql_db_init_sql` output.

Get the master password from Secrets Manager:

```bash
aws secretsmanager get-secret-value \
  --secret-id agrovesto-prod-mssql-master --query SecretString --output text
```

## DNS — this account is authoritative

All public Route53 configuration lives in the prod account: this stack creates
the zone for the root domain and **every record in it**.

- **Prod services** — alias records (`wallet.nomaos.com`, …) → the ALB.
- **Dev** — the dev account creates no zone/records (`manage_dns = false` in
  `dev/terraform.auto.tfvars`); its hosts live under the `dev.<domain>`
  subdomain (`wallet.dev.nomaos.com`, `landing.dev.nomaos.com`, …) and are
  created from here via `extra_a_records` / `extra_cname_records` in
  `terraform.auto.tfvars`, filled from the dev stack outputs
  (`ec2_public_ip` / `frontend_default_domains`).

Cutover order:

1. Apply prod (creates the zone + prod records).
2. Fill `extra_a_records` / `extra_cname_records` for dev and apply again.
3. Delegate the registrar NS records for the domain to this stack's
   `route53_name_servers` output.
4. Apply dev — with `manage_dns = false` it deletes its old self-managed zone
   and switches nginx to `*.dev.nomaos.com`.

## Teardown

`deletion_protection` (ALB + RDS) and `mssql_skip_final_snapshot = false` are
on by default. To destroy: set them off, `terraform apply`, then
`terraform destroy`. ECR repos refuse to delete while they contain images
(`ecr_force_delete = false`) — empty them first or set the flag.
